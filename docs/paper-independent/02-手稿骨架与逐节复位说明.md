## 题名与定位

沿用现稿题名 `Batch-cached egress selection in cross-hook XDP updates`。理由：题名描述事物、不预告枚举，且准确指向 selected entry 与 retained program 的区分；无需为主线的 traffic weaving 让路。

定位语写进 cover letter 与 Abstract 末句：a controlled mechanism study on execution identity across XDP hooks，独立于 rSwitch 平台论文与 assume-breach 安全论文。现稿 PDF Subject 已是 `Computer Networks-oriented controlled mechanism study`。

## 摘要规格

保留现稿 Abstract 的信息骨架，但把独立性与边界前置：

1. 首句给出实现边界：ingress-selected devmap entry 与 physical output bulk queue 保留的 egress program 是两个观察对象。
2. 中间给出 v3 与 v4 的对照：v3 每 arm 2048 帧但只有 singleton cache epochs、无跨代暴露；v4 每 arm 32 个 cache epoch，direct 13 个跨代 epoch 与 365 个 receiver-corroborated conflicts，stable common mux 11 个跨代 epoch、未观察到冲突。
3. 末句必须保留现稿的三重限定：arms 共享一次 boot、暴露不等、使用未限定高频 tracing；因此不估计自然失败率、不建立一般性修复有效性。
4. 增补一句独立性声明：本文不主张平台性能或安全收益，rSwitch 冻结版本仅作 motivating application。

Keywords 沿用现稿：XDP; programmable data plane; consistent updates; devmap; packet identity。

## 关键段落写作规格

**Contribution statement（§1 末）**：沿用现稿的三项 bounded contributions，但把第三项的 stable-common-mux design requirement 明确写成设计必要条件而非已验证修复；同时加一句 non-claim，声明本文不评估 rSwitch 完整图、不主张平台性能或安全收益。

**定义段（§3.1）**：g(f)、s(f)、c(e)、r(f) 逐个给出可观测来源；条件式 epoch 论证的前提（单一 retained object、可区分语义、epoch 内两代共存）必须显式列出，避免被读成普遍定理。

**结果段（§5.2）**：packet 17 的代表性历史要保留全链条，即 `requested A / actually assigned B / selected B/533 / epoch retained A/532 / receiver B ingress and A egress / semantic 1815187358 vs 2067828377`，并注明是 one technical sequence within the controlled campaign，不是独立重复。

**限制段（§6）**：现稿 §6.5 的 `These limits are central to the interpretation, not administrative caveats.` 应保留原意并前置到 §1，防止审稿人把限制当成附录式的免责声明。
