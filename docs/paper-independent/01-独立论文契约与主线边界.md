# 独立论文契约与主线边界

> 用途：把 `PUBLICATION_STRATEGY.md` §3 的 Anti-Salami 规则逐项落到 S1（现稿独立机制论文），并给出与 P1/P2 的边界。
> 依据：现稿全文、`00-A-C-B策略判断与R0纲领对齐.md`、R0 治理文件。所有实验数字均引自现稿，未新增实验。

## 独立研究问题

现稿 §1 与 §4.1 的自述问题：在跨 hook 的 XDP 更新中，一个正确的 ingress-selected devmap entry 能否与另一个 retained egress object 共存于同一 cache epoch；receiver 语义能否佐证该执行历史；selective controls 能否区分替代错误通道；以及 clean 观察是否真的包含跨代暴露。

凝练为可证伪陈述：**当物理输出 bulk queue 在一个 cache epoch 内保留同一个 egress program 时，逐帧的 ingress generation 选择不能单独决定实际执行的 egress 语义。** 现稿 §6.1 把它限定为机制解释，明确不是关于自然部署系统的概率陈述。

该 RQ 不依赖平台性能、不依赖安全收益、不依赖威胁模型与攻击集，满足 `PUBLICATION_STRATEGY.md` §2 对 P1 与 P2 的不得依赖约束的反向检验。

## 独立机制

| 机制 | 现稿位置 | 边界 |
|---|---|---|
| Cache-epoch consistency condition：区分 g(f)、s(f)、c(e)、r(f)，要求 r(f) = g(f) 且保持帧身份 | §3.1 | 依赖可区分语义与固定 direct object，不是关于任意 egress program 的定理 |
| Cache epoch 的操作性定义：从程序安装到最终 FLUSH 的区间，queue-full 传输不产生新 epoch | §3.2 | 源语义与运行时历史在局部一致，不构成 Linux 实现的完整 refinement proof |
| Exposure-aware 诊断：区分 zero errors 与 zero opportunities | §1、§5.1、§6.1 | v3 的零冲突因无跨代暴露而为空真，不得当作修复成功 |
| Stable common mux 与 frame-bound capsule 的设计必要条件 | §3.3、§6.4 | 只在 local path 评估；closure、bank 不可变、capsule 绑定、失败不回退 active generation、延迟帧与 bank 退役均为必要条件；现稿明确 `neither the local mux result nor the component builds establish their enforcement` |

## 独立失败条件

现稿 §6.4 给出的具体 falsifier：已注册路径选了不同对象、frame binding 损坏逃过检测、延迟帧到达被复用的 bank、部分准备的 graph 被激活。§6.2 给出最强 rival：高频 tracing 与 threaded-NAPI 配置对生产者／消费者调度的干预；零 trace loss 只证明收集完整性，不证明非干扰。

补成投稿级停止条件，对齐 `CLAIM_LIFECYCLE.md` §4 与 `KILL_CRITERIA.md` §7：

- 若多次独立 boot、trace-off/on 与等暴露条件下 direct arm 不再出现 receiver-corroborated conflicts，机制解释被削弱或推翻，须记为 `valid-negative`，不得删除。
- 若 common-mux arm 在等暴露且正确 closure 下出现 conflicts，frame-bound dispatch 的设计要求被推翻。
- 若 observer 干预被证明是 epochs 形成的唯一原因，v4 结论降级为仪器效应，论文按 `EXPERIMENT_QUALITY_GATE.md` 的 `invalid-instrumentation` 处理。
- 按 `RESEARCH_CONSTITUTION.md` §5，结果不好、攻击未成功、防御未奏效不得作为 invalid 理由。

## 主要 claim 与 non-claims

**主要 claim**：机制区分（selected entry 与 retained egress object 不是同一观察对象），加上暴露感知的诊断方法（区分零错误与零机会），以及 stable common mux 的设计必要条件。现稿 §7 自述主要结果是机制区分与暴露感知的诊断方法。

**non-claims**（现稿逐节自述，投稿时必须保留）：

- 不估计自然失败发生率，不建立一般性修复有效性（Abstract、§6.3、§7）。
- 不声称 Linux 缺陷，不主张对既有更新机制的优先权（§2.3）。
- 不做 native NIC／driver 性能、P99 延迟、CPU 开销、no-drop 率声称（§6.5）。
- 不执行完整 rSwitch graph、不实现生产策略语义、不跑真实 L-VLAN／L-ACL（§1、§6.3）。
- 不把 0 conflicts 写成 100% correct、基于 2048 独立 trials 的置信界或修复保证（§6.3）。
- 不主张安全收益、有界遏制、流量编织、assume-breach 或任何 jz_sniff_rn 应用结论。

## 与 P1/P2 的边界对账

| 维度 | S1 | P1（Reconfigurable substrate） | P2（Bounded containment） |
|---|---|---|---|
| RQ | 跨 hook 更新中 selected 与 executed identity 的区分 | 可组合、可热更新、可移植的数据平面 | 有界响应是否改善安全／业务 Pareto |
| 机制 | cache-epoch condition、exposure-aware 诊断、common mux 必要条件 | tail-call pipeline、profile 热切换、混合数据面、CO-RE | traffic weaving 抽象、状态机、护栏、验证式回滚 |
| 实验 | veth two-generation slice、六 arm、fault controls、bounded model | OVS／OVS-DPDK 吞吐、pipeline 深度、profile 切换瞬态、多内核 CO-RE | 七条基线、攻击场景、benign look-alikes、消融 |
| primary metric | opportunity epoch、conflict frame、诊断通道 mask | Mpps/Gbps、P50/P99 延迟、切换时间、event loss | 可达资产、横移成功率、业务损害、rollback 失败率 |
| 失败条件 | 多 boot 无冲突、mux 有冲突、observer 干预 | 核心贡献无法区别于已有 XDP 平台、热切换不稳定 | bounded weaving 不优于二元 XDP DROP、业务损害不可测 |
| 主要 claim | 机制区分与诊断方法 | 平台级可重构性 | 有界响应的安全收益 |

`RESEARCH_EXECUTION_PLAN_v0.1.md` 的 G1 要求 P1 与 P2 有不同的主要问题、机制和 evaluation；上表说明 S1 与两者均同时满足该条件。
