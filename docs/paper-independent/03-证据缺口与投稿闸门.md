## Claim Gate 对账

`CLAIM_LIFECYCLE.md` §5 要求进入摘要、贡献列表或结论前全部通过定义清楚、最近邻已检查、反例已记录、实验已完成、原始数据存在、适用边界明确、非适用场景明确、置信度明确、Evidence Lead 已 review、Coordinator 已接受。S1 当前：claim 定义清楚且有可证伪表述；适用与非适用边界在现稿 §6 写得充分；最近邻仅覆盖 Reitblatt、libxdp、devmap 内核语义，未达 `RESEARCH_EXECUTION_PLAN_v0.1.md` WS2 的系统检索判据；无反例登记档案；实验为单次 boot 探索性记录；原始数据在私有 sealed archive；置信度未标注；Evidence Lead review 与 Coordinator 接受均无记录。按 §4 的状态机，S1 的 claim 目前处于 `evidence-seeking`，不能升到 `partially-supported`，更不能以 `supported` 口吻进入摘要。

`CLAIM_LIFECYCLE.md` §6 的禁止模式逐项映射到 S1：`“首次”但无系统检索`、`“显著优于”但无统计`、`“可部署”但未测试失败恢复`、`“通用”但只在单一环境测试`、`“安全”但只测吞吐`、`“可回滚”但只证明配置被删除`。S1 尤其要防第二项与第四项，具体替代表述见 `01-独立论文契约与主线边界.md` 的禁句清单。

## 必须补实验清单

按现稿 §6 自述与 R0 闸门整理，逐项给出判据：

1. **多 boot 独立会话**：每 arm 在独立 session 下重复，预先冻结 repeat count 与 exclusion rules，Q2 预注册后修改需 ADR。
2. **等暴露匹配**：让 direct 与 clean mux 的 opportunity epoch 与实际 A/B 组成可比，或显式采用配对设计；否则不得给出 matched repair estimate。
3. **observer qualification**：trace-off/on、stable generation、singleton 与 multi-frame 历史在相同 offered-load 与时序定义下对照，这是现稿 §6.2 原文要求的 qualification。
4. **packet-level 统计**：按预注册分析计划报分布、置信区间与效应量；不再只报精确计数。
5. **invalid-run 与负结果台账**：按 `EXPERIMENT_QUALITY_GATE.md` 的 run 状态分类记录，保留 `valid-negative`。
6. **artifact 公开**：现稿 Data and code availability 自述未公开，公开后回填 DOI 与第三方可访问声明。
7. **native 或明确不声称**：现稿 §6.5 明确无 i40e／mlx5 实验、Raspberry Pi 5 只做环境可行性检查；若要主张 driver-family 结论，须补 native integrated path，否则维持不声称。
8. **AI 声明补全**：现稿 §4.7 与 Declaration 自述 Codex 参与、model version 未暴露、session date 不能代替 model version、需作者审核批准；投稿前补 model version 与人工责任说明。
9. **版本口径固定**：现稿 [8] 为 `c10fbd8`（`v2.2.0` tag），当前 `dev 8850f7f` 与之分叉；实验 manifest 必须写实际 checkout 的 commit，不得笼统写 `v2.2.0`。
10. **最近邻补检**：按 WS2 完成证据地图与每个核心 claim 的最强近邻标注；本轮未做在线检索，不作新颖性结论。
